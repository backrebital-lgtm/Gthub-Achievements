# راه‌اندازی

مخزن مقصد: `ramincsy/Gthub-Achievements`، با همکار `backrebital-lgtm`.

## دسترسی

- مالک مخزن: ramincsy.
- حساب دوم: دعوت Collaborator با دسترسی نوشتن؛ عضویت تنها پس از پذیرش دعوت فعال می‌شود.
- گردش‌کار CI: فقط خواندن محتوا.
- گردش‌کار ساعتی: خواندن محتوا، نوشتن Issue هماهنگی و واگذاری کار، درخواست بررسی PR. با ثبت یا کنارگذاشتن review در همین مخزن هم اجرا می‌شود؛ checkout فقط شاخهٔ پیش‌فرض است.
- اعتبارسنجی co-author: خواندن محتوا و PR. با وجود توکن خواندن، کد PR اجرا نمی‌شود؛ commitها از API خوانده می‌شوند و اسکریپت از شاخهٔ پیش‌فرض است.
- درخواست بررسی متقابل: خواندن محتوا و نوشتن درخواست review (نه merge). با وجود توکن نوشتن، کد PR اجرا نمی‌شود و فقط شاخهٔ پیش‌فرض checkout می‌شود.
- گزارش پیشرفت: خواندن PRهای بسته‌شده و commit نشسته‌روی شاخهٔ پیش‌فرض (`merge_commit_sha`)؛ Issue یا PR نمی‌سازد. حتی در اجرای دستی، checkout شاخهٔ پیش‌فرض است.
- هیچ PAT، رمز مرورگر یا کلید API در این پروژه ذخیره نمی‌شود.

## فعال‌سازی

1. کد و پوشهٔ `.github/workflows` روی شاخهٔ پیش‌فرض `main` قرار بگیرد.
2. حساب دوم دعوت مخزن را در GitHub بپذیرد.
3. در تب Actions، `Hourly maintenance` را با `Run workflow` اجرا کنید؛ `dry_run` روشن فقط برنامهٔ تغییرات را نشان می‌دهد. برای اعمال تغییرات آن را خاموش کنید.
4. خروجی اجرای موفق و گزارش Summary را بررسی کنید. اگر Issue یا PR باز وجود نداشته باشد، گزارش صرفاً در Summary باقی می‌ماند.
5. قالب Discussions Q&A در `.github/DISCUSSION_TEMPLATE/q-a.yml` است؛ دستهٔ Q&A با slug `q-a` باید باقی بماند. پرسش نمایشی برای نشان نفرستید.

نمونه‌های آغازین:

- [مثال عملی branch، PR، close و merge](examples/branch-pr.fa.md)
- [co-author، ایمیل noreply و Q&A](examples/attribution.fa.md)
- [گردش‌کارهای دو حساب](workflows.fa.md)

هماهنگ‌کننده فهرست Issue و PR را صفحه‌بندی می‌کند؛ اگر صفحهٔ کامل بدون پایان بماند اجرا ناموفق می‌شود. برای بیش از سقف `maxPullsPerRun`، گزارش می‌گوید کدام PRها به‌تفصیل بررسی نشدند و کدام کارهای آماده برای `blocked by` بومی بررسی نشدند. اجرای `npm test` این رفتار را پوشش می‌دهد.

## محدودیت‌ها

نشست Chrome روی کامپیوتر در runner گیت‌هاب در دسترس نیست. `GITHUB_TOKEN` هویت برنامهٔ نصب‌شدهٔ GitHub Actions است و فعالیتش معادل فعالیت شخصی دو حساب نیست.

Quickdraw (بستن ظرف حدود ۵ دقیقه) و YOLO (merge بدون review) در این راه‌اندازی خودکار نمی‌شوند؛ گردش‌کارها Issue/PR را برای نشان نمی‌بندند و approve/merge نمی‌کنند.

گردش‌کار Actions وضعیت کارها را هماهنگ می‌کند. تولید و بررسی هوشمند از طریق وظیفهٔ ساعتی «همکاری ساعتی پروژه GitHub» در Codex مالک پروژه تنظیم شده است؛ تنظیم زمان‌بندی داخل این مخزن ذخیره نمی‌شود. وظیفهٔ محلی به روشن‌بودن کامپیوتر، اجرای Codex، سهمیه و دسترسی به حساب‌ها وابسته است. هیچ کلید API یا رمز حسابی به مخزن اضافه نشده است.

## توقف

از Actions، گردش‌کار `Hourly maintenance` را انتخاب و از منوی آن `Disable workflow` را بزنید. اجرای دستی نیز از همان صفحه ممکن است.

برای توقف کار هوشمند، وظیفهٔ «همکاری ساعتی پروژه GitHub» را در بخش Scheduled برنامه متوقف کنید. این زمان‌بندی و زمان‌بندی Actions جداگانه هستند.
