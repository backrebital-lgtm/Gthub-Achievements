# روال همکاری

## صف کار

Issue باید مسئله و معیار پایان داشته باشد. نگهدارنده پس از بررسی، برچسب `ready-for-work` را اضافه می‌کند. هماهنگ‌کننده در اجرای بعد، کار بدون مسئول را به حسابی که کار باز کمتری دارد واگذار می‌کند. هر حساب حداکثر دو Issue بازِ واگذارشده دارد. کار دارای برچسب `blocked` یا مسئول قبلی دست‌نخورده می‌ماند.

برچسب `priority:high` جلوتر از `priority:normal` پردازش می‌شود. برچسب‌های `area:docs`، `area:automation` و `area:tests` موضوع کار را مشخص می‌کنند.

## بررسی PR

PR غیرپیش‌نویس یکی از دو عضو برای عضو دیگر درخواست بررسی می‌گیرد. درخواست موجود تکرار نمی‌شود. تأیید commit قبلی برای commit تازه کافی نیست. درخواست اصلاح مربوط به commit فعلی در گزارش مشخص می‌شود؛ ابتدا نویسنده آن را رفع می‌کند.

گزارش وضعیت یکی از `needs-review`، `review-requested`، `changes-requested` یا `approved-current-commit` را نشان می‌دهد. این صرفاً وضعیت review است؛ به معنی اجازهٔ merge یا موفقیت تست‌ها نیست. برای بیش از ۲۰ PR، فقط ۲۰ مورد اول هر اجرا به‌تفصیل بررسی می‌شود؛ بقیه نیازمند بررسی باقی می‌مانند.

گردش‌کار هر بار حداکثر شش واگذاری یا درخواست بررسی انجام می‌دهد و یک Issue گزارش را در صورت تغییر به‌روز می‌کند. هیچ PR را با این اسکریپت merge یا approve نمی‌کند. نوشتن محتوا و بررسی کد را وظیفهٔ ساعتی Codex انجام می‌دهد؛ تمام پیام‌های عامل باید خودکاربودن را اعلام کنند.

## معیار ادغام توسط Codex

1. مسئلهٔ مشخص و تغییر مرتبط وجود دارد.
2. تست متناسب با تغییر و CI برای آخرین commit موفق است.
3. diff واقعی بررسی شده و ایراد حل‌نشده ندارد.
4. PR و commit از زمان بررسی تغییر نکرده‌اند.
5. قوانین شاخه رعایت شده‌اند؛ تغییر مجوز و secrets نیازمند بررسی جداگانه است.

کار تمام‌شده با لینک PR در Issue مستند شود؛ پرسش‌ها برای ابهام واقعی همان کار مطرح شوند. فعالیت برای خالی نبودن گزارش یا افزایش شمارنده تولید نشود.

## اجرا و خطا

در `Actions → Hourly maintenance → Run workflow`، گزینهٔ `dry_run` به‌صورت پیش‌فرض روشن است و هیچ واگذاری، درخواست یا Issue جدید نمی‌نویسد. اجرای زمان‌بندی‌شده اعمال تغییرات را فعال می‌کند. تست‌ها پیش از دسترسی نوشتن به API اجرا می‌شوند.

خطای خواندن موقت API حداکثر دو بار تکرار می‌شود. درخواست نوشتن تکرار نمی‌شود، زیرا ممکن است پاسخ گم شده باشد ولی تغییر ثبت شده باشد. نبود دسترسی، rate limit باقی‌مانده و خطای صفحه‌بندی اجرا را ناموفق می‌کند تا گزارش ناقص به‌عنوان موفق منتشر نشود.

با خاموش‌کردن گردش‌کار، هماهنگی خودکار متوقف می‌شود. زمان‌بندی هوشمند Codex را جداگانه در برنامه متوقف کنید.

## مسیر توسعه

- مثال عملی branch، commit و PR همراه با خروجی قابل بررسی.
- راهنمای Q&A برای پرسش‌های واقعی دربارهٔ اجرای مثال‌ها.
- راهنمای انتساب درست commit و co-author برای همکاران واقعی.
- پیگیری رویدادهای عمومی واجد بررسی؛ شمارش رویدادها معادل تأیید نشان توسط GitHub نیست.
